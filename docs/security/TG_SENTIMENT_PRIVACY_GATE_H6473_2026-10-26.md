Этот документ — политика приватности для sentiment-майнинга TG-чатов в SanskritKaraoke.
Статус майнинга кураторов: **GATED-BEFORE-ENABLE** (гейт-механика в

[TG_SENTIMENT_ENABLE_CHECKLIST_H6473_2026-10-26.md](TG_SENTIMENT_ENABLE_CHECKLIST_H6473_2026-10-26.md).

## 1. Аудит доступа коллектора H6455

### Что читается

| канал | что читается | статус |
|---|---|---|
| sk-grade sentiment (H6455) | скоринг-эвенты `POST /api/grade` (без текстов учеников: event_id, ts, verse, score, event_ref) + голоса `POST /api/feedback?event=<id>&vote=up\|down` — одна колонка `sentiment` + отдельная audit-строка в SQLite `data/sentiment/sentiment.db` (.92, env `SK_GRADE_SENTIMENT_DB`) | живо, не TG |
| LLM-судья (H6455/К6) | ТОЛЬКО уже обезличенный `{id, text}` JSONL — входные тексты уходят в OpenRouter (`google/gemini-flash-1.5`), ничего не хранится, вывод в stdout | вручную/офлайн |
| TG-майнинг кураторов (H6455 v2) | Telegram Bot API `getUpdates` с токеном бота `TG_BOT_TOKEN`; скоупинг по чату — **клиентский**: апдейты принимаются по всем текстовым message бота и фильтруются по `chat.id == CURATORS_CHAT_ID` после получения (`CURATORS_CHAT_ID` = `-1002079934542`, константа, переопределяется env владельцем юнита); параметр `allowed_updates` в коде (`[{message:{chat:{id…}}}]`) не является валидным скоупом Telegram (ожидаются типы апдейтов) и **не проверен** — до включения он должен быть исправлен или явно перекрыт строгим клиентским фильтром (чеклист A1); топики/форумы кодом не различаются (`message_thread_id` не проверяется); анонимизатор маскирует `@username`/t.me/email/phone/URL и **отбрасывает** сообщения с вероятным «Имя Фамилия» (drop > mask) по контракту H6252 | **гейт закрыт** (DRY-RUN по умолчанию; `--enable` без гейта → exit 3 `GATE_CLOSED`) |

Доступ бота ограничен тем, где он состоит: чаты, где бот не участник/админ,
недоступны API; боту должен быть добавлен только чат кураторов.

## 2. Ретеншн-политика: сырое vs агрегаты, механика удаления

| слой | срок | механика удаления |
|---|---|---|
| сырые TG-сообщения | **НЕТ ретеншена** — never-persist: `live_fetch` → анонимизация в памяти одного запуска → digest в stdout; файловая/streaming-персистенция сырья запрещена без нового рулинга и ре-гейт-пересмотра | нечего удалять: не создано; проверка — отсутствие файлов в `data/sentiment/*` кроме гейта |
| digest-строки (обезличенные, из stdout-JSONL) | ≤ 30 дней от даты майнинг-запуска; живут только в рабочих файлах анализа на .92 | удаляются файлом после агрегации; в бэкапы окна попадают только до очередного бэкап-тика |
| агрегаты (вердикты/счётчики ≥k, §3) | без ограничения — это несырьё, персоналий не содержат | остаются в отчётах как артефакт решения |
| sk-grade store (events/feedback) | персоналий не содержит (нет user-id); капа: события старше 12 месяцев подлежат подчистке `DELETE FROM events WHERE ts < …` при ближайшей регламентной сессии .92 | удаление строк в SQLite; аудит-строки feedback удаляются той же командой по event_id |

Удаление фиксируется одной строкой в отчёте запуска (что удалено, кем, когда) —
легковесно, без хранения самих данных.

## 3. Разрешения по 152-ФЗ

Жёсткие правила для любого sentiment-майнинга TG (включая будущие изменения кода):

1. **Без имён/юзернеймов/телефонов**: сообщение с вероятным «Имя Фамилия»,
   `@username`, телефоном, email, t.me-ссылкой не попадает в digest — маскируется
   (`[USER]/[PHONE]/[EMAIL]/[LINK]`) или отбрасывается целиком (персоналии в
   маскированных цитатах = drop, не mask — контракт H6252).
2. **Цитаты только обезличенные**: в коммитах/отчётах/docs репо цитаты TG —
   запрещены; обезличенные цитаты допускаются только в рабочих файлах анализа,
   прошедших полный каскад анонимизатора.
3. **Агрегаты ≥k**: любой публикуемый/выгружаемый агрегат по TG-данным считается
   по бакетам ≥ **k=5** отдельных сообщений-источников; бакеты меньшего размера
   поднимаются до порога или выкидываются (anti-reidentification). Авторская
   персоналия в digest не хранится ни в каком виде, поэтому бакеты — по дате/запуску.
4. **Сторонняя обработка**: в LLM-судью уходит только каскадно-обезличенный текст;
   сторонние sentiment-модели — только через @DECIDE-визу (урок H6213).
5. **Нарушение = стоп**: найденное сырое/неперсоналий-очищенное сообщение в любом
   артефакте — немедленный стоп майнинга (гейт закрывается удалением файла
   `data/sentiment/tg_mining.gate`), инцидент-репорт MG.

## 4. Гейт-механика (gated-before-enable)

Майнинг включается одновременным выполнением ВСЕХ условий:

- `SK_TG_MINING_GATE=APPROVED` в env systemd-юнита .92, который запускает утилиту;
- файл `data/sentiment/tg_mining.gate` существует на .92;
- **каждый пункт чеклиста**
  [TG_SENTIMENT_ENABLE_CHECKLIST_H6473_2026-10-26.md](TG_SENTIMENT_ENABLE_CHECKLIST_H6473_2026-10-26.md)
  выверен и подписан MG (виза фиксируется в самом чеклисте).

Закрытие гейта в любой момент: удалить файл гейта (env не важен) — майнинг снова
отказывает exit 3. До открытия гейта пункт TG-майнинга миссии H6455 остаётся
**gated-before-enable** — это by-design состояние, не дефект.
